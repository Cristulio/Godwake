# Audit — broken / dead-end / silently-failing (2026-05-31)

**Scope:** READ-ONLY hunt for things that *don't work properly or at all* — dead-end UI,
half-wired features, swallowed errors, broken interactions, save/load gaps, unreachable content.
Sibling lane `audit-misfit` (PR #223) covers conceptual *misfits* (inert SPD/movement, positional
stats shown as real, dead 5e-isms, cloned blessings, orphan files) — this report does **not**
re-litigate those; it focuses on functional breakage.

**Headline:** the major player-facing systems are wired end-to-end and well covered by tests
(spell dispatch, affix/blessing/quirk/campBoon/upgrade channels, monster action kinds, save
migrations, combat-scoped flag resets, the elite→legendary path, the Shield auto-react + toggle).
The breakage is in the long tail — a wizard AC display gap, an action-economy gating trap for
reaction/bonus spells, a silent-data-loss path on content-id changes, one un-coerced persisted
screen, and dead code. Nothing is fully non-functional; everything below is `MINOR`/`RISKY`/a soft
`DEAD-END`.

## Full findings

### 1. Wizard AC understated out of combat — Mage Armor flag is combat-scoped  · DEAD-END (display)
- **Where:** `engine/character/derived.ts:127` reads `character.resources.mageArmorActive` to add the
  +3; `components/inventory/InventoryScreen.tsx:57,168` renders `computeAC(character)` directly.
- **Why broken (evidence):** `mageArmorActive` is set `true` **only** in `createCombat.ts:203`.
  `initialize.ts:138` defaults it `false`; `actions.ts:125` (`longRest`) resets it to `false` for
  wizards. So between the hub, the first room of a fresh descent, and every post-camp room, a Wizard's
  computed AC omits the +3 Mage Armor the design treats as an always-on class baseline ("Wizards walk
  into every fight already wrapped in Mage Armor", `createCombat.ts:198`).
- **Repro/trace:** Create a Wizard → open Inventory at the hub. AC reads e.g. 12 (10 + DEX 2). Enter
  any fight: combat AC is 15. The inventory readout disagrees with actual durability, and gear-swap AC
  comparisons at the hub are made against the wrong baseline. After a fight it reads "correctly"
  (stale-true), then drops again after a camp long rest — inconsistent across the run.
- **Fix direction:** in `computeAC`, treat Mage Armor as a wizard passive (`classId === 'wizard' && !bodyArmor`)
  rather than reading the combat flag, or have the out-of-combat AC readout force it on for wizards.

### 2. Spells button locks out reaction / bonus-action spells after the action is spent · DEAD-END
- **Where:** `components/combat/ActionBar.tsx:139-144` — `canSpells = … && !character.actionEconomy.actionUsed`.
- **Why broken (evidence):** Misty Step spends only the **bonus** action (`spells/mistyStep.ts:15`,
  `bonusActionUsed: true`); a manual Shield spends only the **reaction** (`spells/shield.ts:18`,
  `reactionUsed: true`). Neither costs the action, but the only way to open the `SpellPicker` is the
  action-gated Spells button. After the wizard casts Fire Bolt / any leveled spell (action spent),
  the button greys out and Misty Step / manual Shield become uncastable for the rest of the turn
  despite the bonus action / reaction being free.
- **Repro/trace:** L3+ Wizard who learned Misty Step → cast Fire Bolt → the Spells button is now
  disabled → the "blink away after attacking" play is impossible; you must cast Misty Step *first*.
- **Severity note:** soft, not hard. Order works (cast the bonus/reaction spell before the action),
  Shield also auto-fires (`shield.ts:tryShieldReaction`), and the sim ranks Misty Step last so most
  wizards never have it. Still a real "affordable but inert when you expect it" gate.
- **Fix direction:** gate the Spells button on "any known spell is castable given the *current*
  action economy" (i.e. allow opening it when a bonus/reaction spell remains affordable), not solely
  on `actionUsed`.

### 3. Silent swallow of unknown content ids + no item-affix id migration · RISKY
- **Where:** `engine/items/affixMods.ts:102-105`, `engine/character/blessings.ts:185-189`,
  `engine/character/quirks.ts:36-40,73-79,92-99` — each `getAffix/getBlessing/getQuirk` is wrapped in
  `try { … } catch { continue }`.
- **Why broken (evidence):** the catches make aggregation tolerant, which is good — but there is **no
  migration** in `stores/persistMigration.ts` that touches `character.equipped[*].rolled.affixes`,
  `character.blessings`, or `character.quirks`. If an affix/blessing id is renamed or removed in
  content (as ids *have* churned — e.g. `pinchpurse-insurance`, `sages-pact` were deleted at the
  upgrade layer), any saved item/soul still carrying the old id silently loses that effect with no
  warning, no toast, and no version bump. The data-loss is invisible.
- **Repro/trace:** rename an affix id in `content/items/affixes.ts`; load a save whose item rolled the
  old id → `aggregateAffixMods` hits the `catch`, the affix is dropped, the item keeps its rolled name
  but loses the stat. No error surfaces.
- **Fix direction:** on load, prune/rename dead affix/blessing/quirk ids from persisted refs in the
  migration (and ideally surface a one-time "an old enchantment faded" notice), so silent stat-loss
  becomes an explicit, testable migration step.

### 4. `level-up` screen is persisted by the autosave without the hub coercion · RISKY
- **Where:** `stores/gameStore.ts:268-272` (`gatherSnapshot`) coerces `screen === 'delve' || 'reincarnation'`
  → `'hub'` but passes `level-up` (and `codex`/`inventory`/`druid-grove`) through untouched. Delve and
  combat are session-only and reset to `null` on load (`scatterSnapshot`, `gameStore.ts:360-361`).
- **Why broken (evidence):** the zustand `persist` middleware writes on every state change, so an
  autosave can capture `screen: 'level-up'`. On reload, `App.tsx:99` renders `LevelUpScreen` while
  `delve === null`. Completing it calls `applyPendingLevelUp` with `resumeIfDelve = false`
  (`gameStore.ts:608`) → lands on hub, losing the in-progress delve (expected, since delve is
  session-only) — but via an inconsistent recovery path compared to the deliberate delve→hub coercion.
- **Repro/trace:** hit a level-up mid-delve, hard-refresh the tab on the Level-Up screen → you
  rehydrate onto the Level-Up screen (not the hub), apply it, and drop to hub.
- **Fix direction:** add `level-up` to the screen coercion in `gatherSnapshot` (route transient
  in-run screens to `hub` on save), or guard `App.tsx`'s `level-up` case on a pending level-up.

### 5. Test-only fixed-layout delve builders place the elite in a `combat` room · MINOR (dead code)
- **Where:** `engine/delve/createDelve.ts` — `createIronCellsDelve` (`:178`), `createAthkatlaDelve`
  (`:250`), `createSpellholdDelve` (`:960,976`), `createUstNathaDelve` (`:1051`) all wrap the elite
  encounter in `combatRoom(...)` (kind `'combat'`), whereas the procedural builder uses `eliteRoom`
  (`:444`, kind `'elite'`).
- **Why broken (evidence):** `drops.ts:48-52` gives `LEGENDARY_DROP_CHANCE.combat = 0` and the
  `EliteRoom` fight/gold choice only renders for kind `'elite'`. In these layouts the elite would be
  a plain fight with no relic and no risk/reward screen. **Not player-visible:** the live game calls
  `createGodwakeDelve` → `buildChapterNodes` (`createDelve.ts:889`), which uses `eliteRoom` correctly;
  the four fixed builders are referenced only from `createDelve.test.ts` / `bossIntel.test.ts`.
- **Fix direction:** delete the four legacy builders (and migrate the two tests to `createGodwakeDelve`),
  or switch their elite slot to `eliteRoom` so the dead code stops carrying a latent inconsistency.

### 6. Dead component files · MINOR (dead code)
- **Where:** `components/creation/CharacterCreationScreen.v1.tsx` (461 lines) and
  `components/combat/EnemyCard.tsx` — neither is imported anywhere in `src` (the live screen is
  `CharacterCreationScreen.tsx`; combat renders enemies via `BattlefieldSprite`).
- **Why it matters:** dead weight that still contains "Coming soon" race/class gating
  (`CharacterCreationScreen.v1.tsx:275,315`) and a stale enemy card — confusing on grep, and a trap if
  anyone re-wires them. (The misfit audit also flags these as orphans.)
- **Fix direction:** delete both files.

### 7. Misty Step / manual-cast spells gate is the only consumer of bonus-action spell flow · MINOR
- Sub-note to #2: there is **no UI affordance** to cast a bonus-action spell *without* also having the
  action available. If a future bonus-action damage/utility spell is added, it inherits the same
  dead-end. The gate should be generalized when #2 is fixed.

## Verified CLEAN (traced end-to-end, no breakage found)

- **Spell dispatch:** all 12 spells in `content/spells` have a matching `effectKey` case in
  `spells/dispatch.ts`; the wizard's L3/L5 pickers offer exactly the learnable set
  (`leveling.ts:availableWizardSpellsForLearn`); `learn-*` features are filtered from the level-up
  feature list and represented by the picker (`LevelUpScreen.tsx:94`).
- **Class mechanics:** every `mechanicKey` (rage, reckless-attack, frenzy, unarmored-defense,
  fighting-style-defense, improved-critical, extra-attack, archery, colossus-slayer, hunters-mark,
  sculpt-spells) resolves via `characterHasMechanic`; sneak-attack/uncanny-dodge/cunning-action/
  action-surge/second-wind are gated on `classId`/`level`/resources and fire. Frenzy is granted via the
  auto-picked Berserker subclass.
- **Affix / blessing / quirk / campBoon / upgrade channels:** every modifier field used in content has
  at least one combat/derived consumer (verified per-channel). Camp-boon pick-time effects
  (vigor/mantle/patience) are applied in `delveStore.pickCampBoon`. Permanent-HP purchases fold the
  delta into live `hp.max` (`metaStore.purchaseUpgrade:198-209` — the previously-fixed bug).
- **Legendaries/sets:** all relic effects ride `AffixModifiers` channels that apply;
  `setActiveLegendaries` re-bakes effects and enforces the class gate; the elite→relic path fires via
  `rollLegendaryDrop` on kind `'elite'` in the live procedural layout.
- **Monster actions:** every action kind in content (attack, multiattack, paralyze, debuff, summon,
  sustain) is handled in both `monsterAttack.ts` and `monsterIntent.ts` — no silent no-op enemy turns.
- **Save/load:** `migrateV1ToV2` defaults every added field, strips dead keys (rageUsesRemaining,
  attunementSlotsBonus, legendaryBonuses, init), and coerces malformed shapes; `scatterSnapshot`
  re-bakes legendary effects; round-trip is test-covered.
- **State leaks:** `createCombat` clears per-class stale flags (rogue/fighter/barbarian/wizard);
  ranger combat-scoped flags (`rangedEvasionRemaining`, opening volley, Hunter's Mark) are
  `CombatState`-scoped; action economy is reset before each combat (`DelveScreen.tsx:183,380`);
  antitoxin poison-immunity is cleared at combat end (`damage.ts:158-171`), not on first hit.
- **UI affordances:** ActionBar gates (Rage/Reckless/Second Wind/Action Surge/Cunning Action/
  Hunter's-Mark/Item) are all correctly conditioned; the Shield auto-fire **toggle** is fully wired
  (CombatHUD button → `handleToggleShieldAutoFire` → `shieldAutoFire` → `tryShieldReaction`);
  RE-MARK and the rage/heal potion gate (the previously-fixed dead-ends) hold. All 10 `Screen` states
  are reachable and rendered; no orphan/empty screens.
- **Content reachability:** all 68 monsters are referenced; all 6 chapter pools are wired into
  `GODWAKE_CHAPTERS`; all 4 robes are in `ARMOR_BASE_IDS` (wizard-gated drops); disabled quirks
  (`enabled: false`) are filtered out of rolls by `listQuirks`.
- **Event effects:** every effect `kind` emitted by content (events + boss-intel) has a handler in
  `applyEventOutcome`; `apply_attack_bonus_run` routes to `delveAttackBonus`/`delveSpellAttackBonus`,
  both consumed.
